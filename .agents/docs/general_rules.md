# AI エージェント作業時の共通ルール

## Git 規約

- 作業は専用ブランチで行ってください。該当するブランチがない場合は新規作成してください。
- 以下の操作は開発者からの明示的な指示がない限り行ってはいけません。
  - `main` ブランチに影響が及ぶ操作
  - 担当外のブランチに影響が及ぶ操作
  - リモートリポジトリに影響が及ぶ操作
- ブランチ名は `<prefix>/<name>`、コミットメッセージは `<prefix>: <summary>` の形式とし、接頭辞 `<prefix>` には以下のいずれかを使用してください。
  - 新機能の開発: `feat`
  - 問題の修正: `fix`
  - 実装の整理: `refactor`
  - ドキュメントの変更: `docs`
  - ユニットテストの変更: `test`
  - ベンチマークの変更: `bench`
  - その他の細かい変更: `chore`

## ファイルの配置

- ライブラリ: `library3372/<category>/<feature>.hpp`
- 内部用ライブラリ: `library3372/internal/<category>/<feature>.hpp`
- ドキュメント: `docs/<category>/<feature>.md`
- ユニットテスト: `tests/<category>/<feature>_test.cpp`
- ベンチマーク: `benchmarks/<category>/<task>/`
- スクリプト: `scripts/<name>.py`

## ファイル名とディレクトリ名

- リポジトリルート直下の慣例的なファイルを除き、ファイル名とディレクトリ名は `snake_case` で統一してください。

## 移植性

- このライブラリのサポート要件は以下のとおりです。
  - C++20 以上
  - GCC 13 以上
  - `char` / `short` / `int` / `long long` が 8 / 16 / 32 / 64 bit 整数
    - これらの `unsigned` 型および `signed char` も同じ bit 長
  - 符号付き整数型が 2 の補数で表現される
  - `float` / `double` が IEEE 754 浮動小数点数規格の binary32 / binary64 フォーマットに従う
  - `__int128` / `unsigned __int128` / `__float128` が利用可能
- 競技プログラミング用途のため、サポート要件を満たさない環境への移植性は考慮しなくてかまいません。
- GCC 拡張を利用できますが、`-std=gnu++XX` のような GNU 拡張モードではなく `-std=c++XX` でコンパイルできるようにしてください。

## YAGNI

- 具体的なユースケースを想定できない機能を追加しないでください。
- 内部用 API を実装する場合、現時点で必要な最低限の機能のみに絞ってください。
- 標準ライブラリや既存の内部用ライブラリを使うことで実装を減らせないか検討してください。

## 外部ライブラリの利用

- 外部ライブラリをコピー & ペーストして実装に利用してはいけません。
- 外部ライブラリを実装上の参考にすることは、ライセンスや利用ガイドラインに抵触しない限り問題ありません。

## 言語

- Markdown 形式のドキュメントは日本語で書いてください。
- ドキュメント以外のファイルでは、コメントや出力文字列を含めて英語のみを使用します。
  - Markdown のコードブロック内のコメントは英語または日本語のうち適当な方を選んでください。
- Git のコミットメッセージと PR のタイトルは英語で書いてください。PR の本文は日本語で書いてください。

## Markdown ドキュメントのスタイル

- 太字や斜体を使わないでください。
- ダッシュやコロンで日本語を繋げないでください。ただし、英単語と日本語、日本語と英単語の組み合わせをコロンで繋ぐことは許容します。
- 絵文字を使わないでください。
- 半角英数字からなる単語の前後にはスペースが入るようにしてください。ただし、句読点に隣接する箇所のスペースは原則として不要です。
- GitHub 上での表示が崩れるのを防ぐため、以下の点に注意してください。
  - インライン数式の開始記号 `$` の直前が全角文字である場合は、スペースを入れるか半角文字に直してください。
  - 数式内の `\{ ... \}` は `\lbrace ... \rbrace` に直してください。
  - 数式内の `| ... |` は `\lvert ... \rvert` に直してください。
- 括弧書きは別の文にすることを検討してください。また、単なる言い換えや例示の括弧書きは削除してください。
- 同じ意味の語句を並列しないでください。
- プロンプトに含まれる言い回しをドキュメントに流用しないでください。
- ノート記法を使わないでください。
