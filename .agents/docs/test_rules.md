# ユニットテスト作成・実行のルール

## ユニットテストの作成

- ユニットテストは公開 API に対してのみ作成します。
- ライブラリの動作が仕様上厳密に正しいか検証してください。主要機能だけでなく補助的な機能もすべてテストしてください。
- テンプレートの場合は、サポートする型がすべてコンパイルでき、かつ正しく動作することを確認してください。
- コピー操作・ムーブ操作をユーザー定義するクラスに限り、これらの操作に対するテストも書いてください。特に自己代入が破綻していないか確認してください。
- 小規模から中規模のランダムケースを複数回ずつテストしてください。
- ランダムケースで生成されにくい特殊ケースや境界値も必要に応じてテストしてください。
- $n = 0$ や空の入力などのエッジケースも忘れずにテストしてください。
- `<cassert>` の `assert` を使ってテスト失敗時に異常終了するようにしてください。
- 乱数生成器は `std::mt19937_64` を使ってください。
  - シード値はあらかじめ生成した固定の乱数値をハードコードしてください。
- アーキテクチャ依存の拡張命令を含むライブラリについては、拡張命令が使えないときのフォールバック実装が用意されているはずなので、拡張命令版とフォールバック版を両方ともテストするようにしてください。
  - 拡張命令版のテストでは、その拡張命令を使えない環境でコンパイル・実行した場合にエラーになるようにしてください。
  - フォールバック版のテストでは `#pragma` や `#undef` により拡張機能を無効化してください。
    - GCC 13 では `#pragma GCC target("no-avx2")` のみでは `__AVX2__` マクロが未定義にならない点に注意してください。

## 通常実行

- テストの一括実行には `scripts/run_all_tests.py` を使ってください。
  ```sh
  python3 scripts/run_all_tests.py
  ```
- 通常実行時は以下のコマンドでコンパイルされます。
  ```sh
  g++ <file> -std=c++20 -march=native -O2 -Wall -Wextra -Wconversion -Wshadow -Werror -I <repository>
  ```
  - `-march=native` により CPU 機能が自動的に有効になります。無効化したい場合はテストコード内で `#pragma` と `#undef` を使ってください。
  - 深い再帰処理に対応するため、実行時のスタックサイズ上限はハードリミットまで自動的に引き上げられます。
  - 実行時制限時間は 1 個のテストあたり 2.0 秒です。
    - 調査用に `--timeout` オプションを用意していますが、最終的には 2.0 秒に確実に収まるようにしてください。
  - 特定のファイルやディレクトリだけを対象にする場合は引数にパスを指定してください。

## サニタイザ付き実行

- 通常ビルドでのテストに加え、`--sanitize` オプションを付けてサニタイザを有効にした状態でもテストを実行し、メモリ不正・メモリリーク・未定義動作が検出されないことを確認してください。
  ```sh
  python3 scripts/run_all_tests.py --sanitize
  ```
  - 特定のファイルやディレクトリだけを対象にする場合は引数にパスを指定してください。
- `--sanitize` 指定時は以下のフラグでコンパイルされます。
  ```sh
  g++ <file> -std=c++20 -march=native -O1 -g -fsanitize=address,undefined -fno-sanitize-recover=all -fno-omit-frame-pointer -Wall -Wextra -Wconversion -Wshadow -Werror -I <repository>
  ```
  - `-fsanitize=address,undefined` により AddressSanitizer・LeakSanitizer・UndefinedBehaviorSanitizer を有効にします。
  - `-fno-sanitize-recover=all` により、未定義動作を検出した際に処理を続行せず異常終了させます。
- 実行時制限時間は 1 個のテストあたり 5.0 秒です。
  - 調査用に `--timeout` オプションを用意していますが、最終的には 5.0 秒に確実に収まるようにしてください。

## CI による確認

- PR 作成時および追加プッシュ時は、GitHub Actions の CI により `tests/` 以下の全テスト（通常実行・サニタイザ付き実行）と `clang-format` チェックが自動実行されます。
- PR を作成・更新した際は、CI の結果が出るまで待機し、すべてのジョブが成功していることを確認してください。
