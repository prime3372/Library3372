# ユニットテスト作成のルール

- ユニットテストは公開 API に対してのみ作成します。
- ライブラリの動作が仕様上厳密に正しいか検証してください。主要機能だけでなく補助的な機能もすべてテストしてください。
- テンプレートの場合は、サポートする型がすべてコンパイルでき、かつ正しく動作することを確認してください。
- コピー操作・ムーブ操作をユーザー定義するクラスでは、これらの操作に対するテストも書いてください。特に自己代入が破綻していないか確認してください。
- 小規模から中規模のランダムケースを複数回ずつテストしてください。
- ランダムケースで生成されにくい特殊ケースや境界値も必要に応じてテストしてください。
- $n = 0$ や空の入力などのエッジケースも忘れずにテストしてください。
- `<cassert>` の `assert` を使ってテスト失敗時に異常終了するようにしてください。
- テストは 100 ms 程度で終わるように設計してください。
  - ユニットテストはパフォーマンス評価が目的ではないので厳密な時間測定は不要です。
- 乱数生成器は `std::mt19937_64` を使ってください。
  - シード値はあらかじめ生成した固定の乱数値をハードコードしてください。
- テストの一括実行には `scripts/run_all_tests.py` を使ってください。
  - `tests/` 以下のすべての `.cpp` ファイルが対象になります。
  - 以下のコマンドでコンパイルされます。
    ```sh
    g++ <file> -std=c++20 -march=native -O2 -Wall -Wextra -Wconversion -Wshadow -Werror -I <repository>
    ```
  - 1 ファイルあたりの実行時間制限は 2.0 秒に設定されています。
  - すべてのテストが通っていることを作業完了時および PR 作成時の必須条件とします。
