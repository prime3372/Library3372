# ドキュメント作成のルール

- `docs/` 以下のユーザー向けドキュメントを書くときに適用されるルールです。

## 基本方針

- ユーザーがライブラリを使うのに必要な最低限の情報のみを記載してください。
- インターフェース上の仕様のみに焦点を当て、内部実装には一切言及しないでください。
- ユーザーはプログラミングと数学に対する基本的な知識を持っていると仮定してかまいません。その範囲を超えている前提知識に限り、軽く補足するか、関連記事へのリンクを貼ってください。
  - 基本的な知識がどこまでを指すかはライブラリのレベル次第と考えてください。
- 内部用のライブラリについてはドキュメントを作成しません。

## 構成

### タイトルと概要

```plaintext
# My Library

ここにライブラリの概要を書く
```

- 「どんなことを」「どれくらいの計算量で」できるかを簡潔に記載してください。
- ライブラリの主要機能に焦点を当て、補助的な機能には言及しないでください。
- 以降のセクションを読んでいなくても理解できるように書いてください。

### テンプレート引数

````plaintext
## テンプレート引数

```cpp
template <typename T>
class MyClass;
```

ここにテンプレート引数の説明を書く

### 制約

- 制約 1
- 制約 2
- 制約 3
````

- ライブラリがクラステンプレートでない場合はこのセクションを省略してください。

### メンバ型

````plaintext
## メンバ型

### Edge

```cpp
struct Edge {
  int from, to;
  T cost;
};
```

ここにメンバ型の説明を書く
````

- ライブラリがクラスでない場合や public なメンバ型を 1 つも持たない場合はこのセクションを省略してください。

### コンストラクタ

````plaintext
## コンストラクタ

```cpp
MyClass::MyClass()  // (1)

MyClass::MyClass(int n)  // (2)

template <typename U>
MyClass::MyClass(const std::vector<U>& v)  // (3)
```

ここにコンストラクタの説明を書く

### 制約

- 制約 1
- 制約 2
- 制約 3

### 計算量

- 計算量 1
- 計算量 2
- 計算量 3
````

- ライブラリがクラスでない場合はこのセクションを省略してください。

### 関数別リファレンス

````plaintext
## get

```cpp
T MyClass::get(int p) const
```

ここに関数の説明を書く

### 制約

- 制約 1
- 制約 2
- 制約 3

### 計算量

- 計算量 1
- 計算量 2
- 計算量 3
````

- コードブロック部分は、静的メンバ関数、非メンバ関数、関数テンプレートの場合はそれぞれ以下のようにしてください。
  ```cpp
  static void MyClass::static_member()
  ```
  ```cpp
  std::pair<long long, long long> not_member(long long a, long long b)
  ```
  ```cpp
  template <typename T>
  void template_function(const std::vector<T>& v)
  ```
- 関数にオーバーロードがある場合は、`## コンストラクタ` と同様に各シグネチャの末尾へ `// (1)`、`// (2)` のように番号を付けてください。
- `operator<<` や `operator[]` などの演算子を提供する場合も、通常の関数と同様に `## operator[]` のような見出しで記載してください。

### 補足

```plaintext
## 補足

ここに補足を書く
```

- 特に補足する事項がない場合はこのセクションを省略してください。
- 小見出し `### ...` を作ってもかまいません。

### 使用例

````plaintext
## 使用例

```cpp
ここに使用例のソースコードを書く
```
````

- コンパイル可能で実行結果が分かりやすいコード例を示してください。
- コード中のコメントは「何が出力されるか」のみを記載してください。

## 注意点

### 制約

- 制約を文章で述べる場合は端的な一文にまとめてください。文末は「～こと」を付けず常体で言い切り、末尾に「。」は付けないでください。
- 特定のオーバーロードに適用される制約は `(1): $n \geq 0$` のように書いてください。
- 制約が 1 つもない場合は `### 制約` セクションを省略してください。

### 計算量

- 計算量は「最悪計算量」「期待計算量」「償却計算量」の中から適切なものを 1 つ選んで記載してください。
  - 最悪計算量の場合は `最悪 $O(T)$` ではなく単に `$O(T)$` と書いてください。そうでない場合は `期待 $O(T)$` や `償却 $O(T)$` のように書いてください。
- 特定のオーバーロードに適用される計算量は `- (1): $O(n)$` のように書いてください。
- 時間計算量と空間計算量が異なる場合は `- 時間 $O(n\log{n})$ 空間 $O(n)$` のように書いてください。

### 特殊メンバ関数

- 特殊メンバ関数のうちデフォルトコンストラクタのみを `## コンストラクタ` セクションに記載します。
- コピー操作・ムーブ操作・デストラクタは明示的に定義する場合でも記載しません。
  - これらについて特筆すべき事情がある場合は `## 補足` セクションに書いてください。

### コードブロック

- コードブロックにおいて以下は省略してください。
  - `inline` 指定子
  - `explicit` 指定子
  - `requires` 節
  - 属性構文 `[[...]]`
  - `__attribute__`

### スタイル関連

- 太字や斜体を使わないでください。
- ダッシュやコロンで日本語を繋げないでください。ただし、英単語と日本語、日本語と英単語の組み合わせをコロンで繋ぐことは許容します。
- 絵文字を使わないでください。
- 半角英数字からなるトークンの前後にはスペースが入るようにしてください。ただし、句読点に隣接する箇所のスペースは不要です。
- 括弧書きは別の文にすることを検討してください。また、単なる言い換えや例示の括弧書きは削除してください。
- 同じ意味の語句を並列しないでください。
- プロンプトに含まれる言い回しをドキュメントに流用しないでください。
- ノート記法を使わないでください。
