# ベンチマーク作成のルール

## ディレクトリ構成

- `benchmarks/<category>/<task>/`
  - `problem.md`: 問題定義
  - `task.json`: タスク設定
  - `generators/`: 入力生成プログラムの `.cpp` ファイル
  - `solutions/`: 解答プログラムの `.cpp` ファイル

## 問題定義

- 最初にタイトルとして `# <task>` を書いてください。
- 以下のセクションに分けて問題を作成してください。
  - `## 問題文`
  - `## 制約`
  - `## 入力`
  - `## 出力`
- `## 入力` セクションには入力形式を plaintext コードブロックとして記載してください。以下はその例です。
  ```plaintext
  N
  A_1 A_2 ... A_N
  ```
- `## 出力` セクションには計算結果をハッシュする手順を書いてください。
  - 最終的なハッシュ値は 1 つの 64 bit 符号なし整数でなければいけません。
  - ハッシュには `library3372/internal/hash/hash_combine.hpp` を使うことを推奨します。
  - 問題の性質上一意なハッシュ値を定義できない場合は、常に `0` を出力するものとします。
- 入出力サンプルを用意する必要はありません。
- 番号付けは基本的に 1-indexed としますが、必要に応じて 0-indexed を使ってもかまいません。

## タスク設定

### 設定例

```json
{
  "runs": 5,
  "timeout_sec": 10.0,
  "cases": [
    {
      "name": "random_small",
      "generator": "random.cpp",
      "args": ["1000"]
    },
    {
      "name": "random_large",
      "generator": "random.cpp",
      "args": ["500000"]
    },
    {
      "name": "worst_small",
      "generator": "worst.cpp",
      "args": ["1000"]
    },
    {
      "name": "worst_large",
      "generator": "worst.cpp",
      "args": ["500000"]
    }
  ]
}
```

### 全体で設定する項目

- `runs` には 1 つの組み合わせに対する反復実行回数を指定します。省略時の値は `5` です。
- `timeout_sec` には 1 回の実行における秒単位の制限時間を指定します。省略時の値は `10.0` です。
- `cases` には生成する入力データの定義を配列で並べます。

### ケースごとに設定する項目

- `name` には出力結果へ含めるケース名を指定します。省略時は入力生成プログラム名と引数から自動決定します。
- `generator` には `generators/` からの相対パスで `.cpp` ファイルを指定します。
- `args` には入力生成器を起動する際に渡すコマンドライン引数の配列を指定します。省略時は空の配列になります。

## 入力生成プログラムの実装

- 生成した入力を標準出力に書き出してください。
- 数列の長さ $N$ やクエリ数 $Q$ などの規模を表すパラメータはコマンドライン引数から受け取る仕様にしてください。
  - ケース設定時は、最悪ケースにおける実行時間が小さくなりすぎないようにパラメータを調整してください。
- 乱数生成器は `std::mt19937_64` を使ってください。
  - シード値はあらかじめ生成した固定の乱数値をハードコードしてください。
- ドキュメント上の計算量オーダーに到達する入力を必ず含めてください。

## 解答プログラムの実装

- `library3372/internal/chrono/timer.hpp` を使って実行時間を計測してください。
  - 複数の計測区間を作ることも可能です。
  - 出力する時間の単位は秒とし、非負の実数で表現してください。
  - 計測した実行時間は以下の形式で出力してください。
    ```plaintext
    time <section> <sec>
    ```
  - 1 つ以上の区間を出力し、区間名が重複しないようにしてください。区間名はスペースを含んではいけません。
- 計算結果のハッシュ値を `problem.md` に従って計算し、以下の形式で出力してください。
  ```plaintext
  hash <value>
  ```
  - 値が `0` の場合を除き、先頭に `0` を付けないでください。
- 実装上の制約により入力データを処理できない場合は、計測を行わずに処理をスキップできます。その場合は以下のように出力してください。
  ```plaintext
  skip <reason>
  ```
  - `reason` は省略可能です。
  - `hash` 行や `time` 行は出力せず、終了コード `0` で終了してください。
- 標準出力には上記の行以外を出さないでください。空行は無視されます。
- デバッグ用のログを出したい場合は標準エラー出力を使ってください。

### 実装例

```cpp
#include <iostream>
#include <vector>

#include "library3372/internal/chrono/timer.hpp"

int main() {
  int n;
  std::cin >> n;
  std::vector<long long> a(n);
  for (int i = 0; i < n; ++i) std::cin >> a[i];

  // 入力仕様の上限を超える場合は計測対象から外す
  if (n > 100000) {
    std::cout << "skip N > 100000\n";
    return 0;
  }

  library3372::internal::Timer timer;

  // 構築処理の実装
  
  double build_sec = timer.elapsed();

  timer.reset();
  unsigned long long ans_hash = 0;

  // クエリ処理の実装とハッシュ値の計算
  
  double query_sec = timer.elapsed();

  std::cout << "hash " << ans_hash << "\n";
  std::cout << "time build " << build_sec << "\n";
  std::cout << "time query " << query_sec << "\n";
  return 0;
}
```

## 計測の実行

- 計測には `scripts/run_benchmarks.py` を使います。

```sh
python3 scripts/run_benchmarks.py
```

- 引数を省略すると `benchmarks/` 以下の全タスクを検索して実行します。特定のタスクディレクトリやカテゴリディレクトリを引数に渡すと対象を絞り込めます。

### オプション

- `--runs` は `task.json` に書かれた反復回数を上書きします。
- `--timeout` は `task.json` に書かれた制限時間を上書きします。
- `-c` または `--case` にケース名を指定すると該当ケースだけを実行します。
- `-s` または `--solution` に解答プログラム名を指定すると該当実装だけを実行します。

### 実行と集計の仕組み

- コンパイルには次のコマンドが使われます。
  ```sh
  g++ <file> -std=c++20 -march=native -O2 -Wall -Wextra -I <repository>
  ```
- 実行時の負荷干渉を避けるため、各プログラムは並列ではなく一つずつ順番に実行されます。
- 深い再帰処理に対応するため、入力生成プログラムおよび解答プログラムのスタックサイズ制限はハードリミットまで引き上げられます。
- 各組み合わせを規定回数実行し、区間ごとに実行時間の中央値を算出します。
- 同一入力に対して正常終了したすべての解答プログラムでハッシュ値が一致するか検証します。不一致や実行時エラーが発生した場合は異常終了として終了コード `1` を返します。

### 結果の報告形式

- 実行結果は整形された JSON として標準出力へ出力されます。

```json
{
  "ok": true,
  "tasks": [
    {
      "task": "benchmarks/category/task_name",
      "runs": 5,
      "timeout_sec": 10.0,
      "cases": [
        {
          "name": "random_small",
          "generator": "random.cpp",
          "args": ["1000"],
          "hash": "123456789",
          "solutions": {
            "fast": {
              "status": "OK",
              "hash": "123456789",
              "medians_sec": {
                "build": 0.001234,
                "query": 0.012345,
                "total": 0.013579
              }
            },
            "naive": {
              "status": "SKIP",
              "reason": "N > 100000"
            }
          }
        }
      ]
    }
  ]
}
```

- ルートの `ok` には全タスクが正常に完了したかを示す真偽値が入ります。
  - 全タスクで実行前処理のエラーがなく、全ケースでハッシュ値が一致し、かつ全解答の `status` が `OK` または `SKIP` であれば `true` になります。そうでなければ `false` になります。
- `tasks` 配列には各タスクの結果を表すオブジェクトが格納されます。
  - タスク設定に不備がある場合や、コンパイルまたは入力生成に失敗した場合、そのタスクオブジェクトは `task` と `error` のみを持ち、ルートの `ok` は `false` になります。`error` にはエラーの内容を表す文字列が入ります。
- 各ケースのオブジェクトと解答プログラム別の結果は次の構成になります。
  - 各ケースの `hash` には解答プログラム間のハッシュ文字列が入ります。不一致または該当する解答がない場合は `null` になります。
  - `solutions` は、`solutions/` からの相対パスから拡張子を除いた名前をキーとし、各解答プログラムの結果オブジェクトを値とする連想配列です。
  - 各解答の `status` には以下のいずれかが入ります。
    - `OK`: 正常終了
    - `SKIP`: スキップ
    - `TLE`: 実行時間制限超過
    - `RE`: 異常終了
    - `INVALID`: 出力形式違反
    - `HASH_ERROR`: ハッシュ値の不一致
  - `status` が `OK` の場合は、その解答が出力した `hash` と区間ごとの秒単位中央値を格納した `medians_sec` が含まれます。`medians_sec` に `total` が含まれていない場合は、各反復における全区間時間の和から求めた中央値が `total` として追加されます。
  - `status` が `SKIP` の場合、理由が指定されていれば `reason` に格納されます。
  - `status` が `OK` / `SKIP` 以外の場合は `error` にエラーの詳細が格納されます。
