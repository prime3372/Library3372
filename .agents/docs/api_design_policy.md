# API 設計方針

- ライブラリの公開 API の設計に関する方針です。`library3372/internal/` 以下のコンポーネントや private メンバなどの非公開 API には適用されません。
- C++ のコード全般に対するルールは `.agents/docs/cpp_coding_rules.md` に書いてあります。そちらも合わせて参照してください。

## 基本原則

- ユーザーの思考負荷を最小化する設計を選んでください。
- 仕様を熟知していなくてもバグが起きにくい設計にしてください。
- 既存のライブラリとの一貫性を保ってください。
- 上記の原則が満たされる範囲内で、タイピングのコストが少ない API を作ってください。
  - 短く打てることは重要ですが、そのせいでバグを引き起こしたり、意味を思い出す手間が増えたり、可読性を損なったりするならば意味がありません。

## 命名

- 最も自然で標準的な名前を一つ選んでください。
  - 必要に応じて AtCoder Library や他の著名ライブラリを参考にしてください。
- 関数名は短い方が好ましいですが、仕様上の誤解が生じない程度にとどめてください。
  - ある機能に対して広く使われている名前がある場合、それは仕様上の誤解を生じないとみなしてよいです。
- 既存ライブラリで同等の機能に命名を行った前例がある場合、それに合わせるのが望ましいです。

## 仕様の統一

### 0-indexed vs 1-indexed

- 常に 0-indexed を使います。

### 半開区間 vs 閉区間

- 原則として半開区間 `[l, r)` を使います。
- 閉区間や「左端 + 長さ」による形式は、特別な理由がない限り採用しません。

### 整数型

- 配列のサイズなど、明らかに `int` に収まる場合は `int` を使います。`std::size_t` は使用しません。
- 整数演算ユーティリティなど、任意の整数型に対応する必要がある場合はテンプレートとして実装します。
  - この場合は `bool` や `char` も整数型とみなします。
- ビット演算やハッシュ値など、符号なし整数が自然な文脈では符号なし整数型を使います。テンプレートで受け取る場合は型制約として強制します。
- 上記のいずれにも該当しない場合は `long long` を使います。

### 浮動小数型

- 浮動小数を扱うライブラリでは、`float` / `double` / `long double` / `__float128` がすべて入力できるようにしてください。
- 入力型から出力型が決まらない場合は `double` を既定の型とし、必要に応じてテンプレート引数で変更できるようにしてください。

### 無効値

- 無効値は、入力そのものは正常だが、入力に対応する有効値が存在しない場合に返します。
- 入力そのものが異常である場合は、無効値を返すのではなく `<cassert>` の `assert` により実行時エラーとしてください。
- 数列の添字やグラフの頂点番号などは `-1` を無効値とします。
- 配列は、有効値が常に非空である場合、空配列を無効値とします。
- 無効値として適当な値が存在しない場合は `std::optional` で無効値を表現します。

### 無限大・無限小

- 無限大・無限小にあたる数値は、適切な値を機械的に決定できる場合を除き、ユーザーが指定する仕様にします。
  - 機械的に決定できる場合はユーザーに委ねるのではなくライブラリ内部で管理してください。

### 特殊メンバ関数

- コピー操作はディープコピーになるように設計してください。
- ムーブ操作を実装する場合は、ムーブ後のオブジェクトが安全に破棄でき、かつ再代入可能な有効状態を保つように設計してください。
- 動的に確保したメモリはデストラクタで破棄してください。

### 継承

- 派生クラスを公開 API として提供する場合、基底クラスはコピー不可・ムーブ不可の抽象クラスとしてください。
- 基底クラス経由で破棄され得る場合は public な仮想デストラクタを、そうでない場合は protected なデストラクタを用意してください。
- 基底クラスが状態やメソッドを一切持たない場合は上記の限りではありません。

### デフォルト引数

- デフォルト関数引数やデフォルトテンプレート引数は、デフォルトの挙動がユーザーの目線で明らかな場合のみ使用してください。

### グラフ

- クラスの場合は `add_edge` で辺を追加する形式にしてください。
- 関数の場合は隣接頂点リストまたは辺リストを入力する形式にしてください。
- 可能ならば自己辺や多重辺が入力されても正しく動作するようにしてください。
